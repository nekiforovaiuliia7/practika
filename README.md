# practika

Отчет по практике: Веб-приложение для управления задачами 


1. **Планирование**  
   - Составлен план этапов: настройка среды → проектирование БД → разработка → тестирование → деплой.  
   - Проблема: изначальные требования были нечеткими (уточнял у руководителя).  

2. **Проектирование БД**  
   - Созданы таблицы:  
     - `Пользователи` (id, логин, хеш_пароля)  
     - `Задачи` (id, название, статус, срок, id_пользователя)  
     - `Категории` (связь "многие-ко-многим" с задачами).  
   - Ошибка: забыл привязать задачи к пользователю (исправил добавлением `user_id`).  

3. **Базовый функционал (CRUD + авторизация)**  
   - Реализовано: регистрация, вход, добавление/удаление/редактирование задач.  
   - Проблемы:  
     - Путаница с `current_user` (вызывал ошибки доступа).  
     - Циклические импорты между файлами.  
   - Решение: использовал `@login_required` и разделил код на модули.  

4. **Интерфейс (шаблоны)**  
   - Созданы страницы: список задач, формы, авторизация.  
   - Применен Bootstrap для стилей.  
   - Ошибка: синтаксические ошибки в Jinja2 (например, пропущенные `%}`).  

5. **Дополнительные функции**  
   - Добавлены категории задач.  
   - Создан простой API для вывода задач в формате JSON.  
   - Ошибка: API временно показывал задачи всех пользователей (исправил проверкой прав).  

6. **Тестирование**  
   - Найдены критические уязвимости:  
     - XSS: ввод скриптов в описание задачи.  
     - Доступ к чужим задачам через подмену ID в URL.  
   - Решение: экранирование вывода и проверка прав доступа.  

7. **Деплой**  
   - Развернул приложение на Heroku.  
   - Проблемы: забыл добавить зависимости в `requirements.txt`, ошибки конфигурации БД.  

---

Рекомендации по исправлению ошибок:
1. **Безопасность**  
   - Всегда экранировать вывод в шаблонах: `{{ task.description }}` вместо `{{ task.description | safe }}`.  
   - Добавить проверку прав для каждой операции:  
     ```python  
     if task.user_id != current_user.id:  
         abort(403)  # Запретить доступ  
     ```  

2. **Оптимизация кода**  
   - Вынести бизнес-логику из view-функций в отдельные файлы (например, `services.py`).  
   - Использовать Blueprints для структурирования роутов.  

3. **Работа с данными**  
   - Внедрить Flask-Migrate для управления изменениями БД.  
   - Добавить валидацию сроков выполнения задач (не разрешать прошедшие даты).  

4. **Тестирование**  
   - Написать unit-тесты для критических функций (например, проверка прав доступа).  
   - Проверить все API-эндпоинты на отсутствие утечки данных.  

5. **Деплой**  
   - Хранить секретные ключи в переменных окружения (не в коде!).  
   - Добавить пагинацию для больших списков задач.
